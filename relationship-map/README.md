# Relationship Map

Отдельный проект редактора карт взаимосвязей. React Flow отвечает за граф, shadcn/ui — за элементы управления, JSON — за общий контракт редактора и агента. Карта может описывать код, сущности БД, процессы или черновую архитектуру.

В основном расширении этот редактор встроен в Webview, а инструменты карт зарегистрированы в существующем MCP vc-ve-tools. Отдельный сервер при таком использовании не нужен. Подробнее: [интеграция в расширение](../docs/RELATIONSHIP_MAPS.md). Ниже описан автономный режим разработки.

## Запуск

```powershell
npm.cmd install
npm.cmd run dev
```

Откройте `http://127.0.0.1:5178`. API работает на `127.0.0.1:4178`. Для сборки: `npm.cmd run build`, затем `npm.cmd start` и `http://127.0.0.1:4178`.

Навигация: колесо прокручивает карту, Ctrl+колесо меняет масштаб вокруг курсора, зажатая средняя кнопка или пробел с перетаскиванием двигают карту. Нижняя панель включает выбор (V), руку (H) и постановку узлов: выберите тип и нажмите на свободное место канваса. Связь создаётся перетаскиванием от правого порта узла к левому порту другого узла.

Папка `maps/` хранит карты при локальной разработке. `extension.json` — копия исходной карты расширения. Другой каталог можно задать через `RELATIONSHIP_MAP_DIR`; в установленном плагине поддерживается `PLUGIN_DATA`. Для совместной работы редактора и MCP укажите им один и тот же каталог. Сохранение требует актуальной ревизии; прежняя версия попадает в `.history/` выбранного каталога для сравнения. Экспорт/импорт JSON работает в браузере.

Узлы могут представлять классы, методы, таблицы, процессы, события и произвольные сущности. Типы, подписи и цвета задаются отдельно для каждой карты (`nodeKinds`, `edgeKinds`), а `entityRef` хранит идентификатор объекта в исходной системе. Произвольные `attributes` узла, например сигнатура, контракт и ответственность метода, показываются и редактируются только в сайдбаре; агент может добавлять подходящие поля в JSON карты. Флажок «Дополнительный узел» скрывает детали при общем обзоре. `east-express-demo.json` показывает формат класса, методов и вызова; все его ID вымышлены.

## Агент

После сборки `node dist/server/mcp.js` запускает локальный MCP сервер через stdio. Инструменты: `list_maps`, `read_map`, `save_map`, `get_map_changes`. Корневые `plugin.json` и `mcp.json` содержат переносимый манифест; `.codex-plugin/plugin.json` и `.mcp.json` — совместимость с Codex. `skills/map-workflow/SKILL.md` описывает работу агента.

Плагин пока локальный и не опубликован или установлен в Codex. Для запуска через плагин нужна установленная Node.js, выполненная сборка и совместимый хост локального stdio MCP. Web UI и MCP обращаются к одному каталогу карт, но это разные процессы.

Карта и её изменение **не исполняют** код, SQL или действия во внешних приложениях. Агент может прочитать разницу ревизий и предложить реализацию, которую затем проверяют и выполняют в контексте конкретного проекта. Подробные границы и следующий этап описаны в `DESIGN.md`.
