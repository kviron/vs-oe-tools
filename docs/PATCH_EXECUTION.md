# Выполнение отдельного патча через MCP

`execute_patch` запускает штатный `bin/OEPatch.exe` из Extension Host.
Передайте `role` (`main`/`test`), `patchFile`, `expectedDatabase`,
`expectedHost`, `expectedPort`. Путь файла может быть абсолютным или относительным
к открытому workspace. При несовпадении цели с Vars.bat/rdboadm.ini запуск запрещён.

Для пакетного хотфикса передайте `packageChanges: "allowAndLog"`: исполнитель
добавит `-allowandlogpkgchanges`. Этот режим показывается в подтверждении и
возвращается в результате. По умолчанию дополнительное разрешение не включается.
Не сочетайте этот режим с отключением пакетного лога через `SetSysParam` в патче.

Принимается один файл `.rde` или `.sql` в Windows-1251 без BOM, до 5 МБ.
VS Code показывает его точный текст, SHA-256 и подключение перед подтверждением.
Исполняется копия прочитанных байтов в отдельной папке Temp; исходный файл не меняется.
Директивы патча (GenerateGUID, SetExecParams, SetSysParam) обрабатывает OEPatch,
расширение не разбивает и не переписывает SQL.

Результат содержит цель, SHA-256, `executed`, `passed`, каталог запуска и журнал.
Успех требует exit code 0, файла `.donepatch` и пустого журнала ошибок.
Это подтверждение выполнения исполнителем; бизнес-результат проверяется отдельно.
После начала выполнения ошибка возвращается с `mayHavePartialChanges: true`.
COMMIT внутри патча может сохранять часть изменений: автоматического повтора нет.
При таймауте транспорта сначала проверьте журналы и базу; не повторяйте запуск вслепую.

Файлы и журналы остаются в каталоге запуска для расследования. Профильный пароль
не передаётся агентом и не включается в команду: OEPatch использует `db` из rdboadm.ini.
Инструмент не устанавливает все пакеты и не запускает OEPrjScript.
